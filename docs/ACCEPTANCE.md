# سناریوهای پذیرش قابلیت‌ها (Acceptance Scenarios)

هر قابلیت با یک سناریوی کوتاهِ قابل اجرا در نسخهٔ آنلاین تست می‌شود. پیش‌نیاز مشترک: افزونه روی وردپرس خام فعال باشد و کاربر جاری admin باشد (مگر خلاف آن ذکر شود).

## قابلیت ۱ — مدیریت کامل وظایف
**سناریو:** در تب Tasks روی New Task کلیک → عنوان «طراحی صفحه ورود» + توضیحات → Create → پیام موفقیت «The task was created.» و ردیف جدید در جدول. همان ردیف را Edit کنید، عنوان را تغییر دهید → به‌روزرسانی فوری. Delete + تأیید → حذف از جدول. صفحه را Refresh کنید → داده‌ها پایدار (MySQL).
**نتیجهٔ مورد انتظار:** عملیات همه با پیام موفقیت/خطای قابل فهم و ذخیرهٔ پایدار.

## قابلیت ۲ — جزئیات و وضعیت وظیفه
**سناریو:** فرم جدید را باز کنید → فیلدهای عنوان/توضیحات/اولویت (کم تا فوری)/سررسید/وضعیت (جدید، در حال انجام، تکمیل‌شده) موجودند. وضعیت را «در حال انجام» ذخیره کنید → Badge وضعیت در فهرست/کانبان تغییر کند. با تغییر وضعیت به «تکمیل‌شده» در کشوی وظیفه، «Completed on» درج شود.
**نتیجه:** ذخیرهٔ همهٔ فیلدها و تغییر وضعیت با ثبت زمان تکمیل.

## قابلیت ۳ — پروژه‌ها و برچسب‌ها
**سناریو:** تب Projects → New Project «وب‌سایت» با رنگ → ایجاد. تب Tasks → فرم وظیفه → انتخاب پروژهٔ «وب‌سایت» + انتخاب برچسب‌های design و bug (در صورت نبود، از کشوی وظیفه با فیلد Tag name بسازید) → ذخیره. در فهرست، Badge رنگی پروژه و چیپ برچسب‌ها دیده شود؛ فیلتر Project = وب‌سایت فقط همین وظیفه را برگرداند.
**نتیجه:** ارتباط وظیفه با پروژه/برچسب و گروه‌بندی + فیلتر.

## قابلیت ۴ — تخصیص به کاربران
**سناریو:** فرم وظیفه → فیلد Assignee → انتخاب کاربر editor → ذخیره. با حساب editor وارد شوید → زنگ اعلان شمارش ۱+ و پیام «...به شما محول شد»؛ در فهرست او وظیفه را می‌بیند.
**نتیجه:** تخصیص از کاربران وردپرس + نمایش وظایف محول‌شده.

## قابلیت ۵ — سطوح دسترسی
**سناریو (سمت سرور):** با حساب author از کنسول مرورگر:
`fetch('/wp-json/taskflow/v1/tasks/1', {method:'PUT', headers:{'X-WP-Nonce': wpApiSettings?.nonce || TaskFlowBoot.nonce, 'Content-Type':'application/json'}, body:'{"title":"هک"}'})` → پاسخ **403**. GET /tasks با author → فقط وظایف خودش/محول‌شده. با subscriber → GET /tasks → 403 کامل.
**نتیجه:** کنترل مجوز در سرور، نه فقط در رابط کاربری.

## قابلیت ۶ — جستجو و فیلتر
**سناریو:** در Tasks عبارتی از عنوان را در جستجو تایپ → نتایج زنده. فیلترها: Status=In Progress، Priority=Urgent، Assignee، Project، Tag، تیک Only overdue → ترکیب فیلترها درست عمل کند؛ Sort by = Priority/Due date → ترتیب درست. Reset filters همه را پاک کند.
**نتیجه:** جستجوی عنوان + فیلتر چندگانه + مرتب‌سازی.

## قابلیت ۷ — نمای فهرست و Kanban
**سناریو:** تب Kanban → سه ستون (New / In Progress / Completed) با شمارنده. کارت را با درگ به ستون «در حال انجام» ببینید → پیام موفقیت و جای‌گیری در ستون (روی موبایل: منوی Move to… روی کارت). بعد از Refresh جای وظیفه پایدار بماند.
**نتیجه:** دو نمای کاربردی و ثبت تغییر وضعیت با جابه‌جایی.

## قابلیت ۸ — تاریخچهٔ فعالیت‌ها
**سناریو:** کشوی یک وظیفه → بخش History: «Created the task …»، «Changed the status …»، «Changed the assignee …» هر کدام با نام کاربر و زمان. تب Activity → فید کامل همهٔ وظایف.
**نتیجه:** ثبت ایجاد/ویرایش/تغییر مسئول/تغییر وضعیت با زمان و کاربر.

## قابلیت ۹ — داشبورد آماری
**سناریو:** تب Dashboard → کارت‌های کل وظایف/باز/تکمیل‌شده/عقب‌افتاده. یک وظیفهٔ جدید بسازید → «کل وظایف» و «باز» یکی زیاد شود. یک وظیفه با سررسید گذشته بسازید → «عقب‌افتاده» زیاد شود. نرخ تکمیل و نمودار اولویت/پروژه مطابق داده باشد.
**نتیجه:** آمار واقعی و زنده، نه دادهٔ ثابت.

## قابلیت ۱۰ — اعلان‌ها و ایمیل (Mock)
**سناریو:** تخصیص وظیفه به کاربر دیگر → زنگ اعلان او + یک ردیف در Mail (Mock) → Outbox با موضوع حاوی MOCK و زمان. تب Mail → Compose → ارسال → در Outbox ثبت. Simulate incoming e-mail → در Inbox با حالت خوانده‌نشده.
**نتیجه:** شبیه‌سازی کامل ارسال/دریافت با گزارش رویداد، همه با برچسب MOCK.

## قابلیت ۱۱ — پرداخت Mock
**سناریو:** تب Payments (Mock) → New simulated payment → مبلغ ۱۰۰ و نتیجهٔ pending → ردیف جدید با شناسهٔ TFMOCK-… و وضعیت در انتظار → دکمهٔ Finalize as successful → وضعیت موفق + به‌روزرسانی جمع‌ها. یک پرداخت failed هم بسازید.
**نتیجه:** جریان کامل success/failed/pending بدون تراکنش واقعی و با برچسب MOCK.

## قابلیت ۱۲ — تنظیمات و خروجی داده
**سناریو:** تب Settings → تغییر ارز به IRT و per page → Save → پیام موفقیت. Data → Export CSV → فایل با ردیف‌های وظایف (فارسی سالم در Excel). Import → قالب نمونه را دانلود، مقداری وظیفه اضافه و Import کنید → گزارش «X created». بخش Uninstall behavior توضیح رفتار حذف را نشان می‌دهد (پیش‌فرض: حفظ داده‌ها).
**نتیجه:** تنظیمات + خروجی CSV/JSON + ورود CSV + رفتار مستند حذف.

## قابلیت‌های خلاقانه

### ★ خلاقانه ۱ — نظرات و @منشن
**مسئله:** هماهنگی تیمی داخل زمینهٔ وظیفه بدون خروج از افزونه.
**سناریو:** کشوی وظیفه → «Ping @editor لطفاً بررسی کن» → Send → نظر زیر وظیفه با آواتار و زمان؛ حساب editor: اعلان زنگ + ایمیل MOCK «You were mentioned».
**معیار پذیرش:** ذخیرهٔ نظر، resolve شدن منشن به کاربر واقعی، اعلان + ایمیل Mock.
**تست خودکار:** `CommentsTimeTest`.

### ★ خلاقانه ۲ — تایمر ثبت زمان
**مسئله:** برآورد واقعی زمان صرف‌شده برای هر وظیفه (گزارش ساعتی به کارفرما).
**سناریو:** کشوی وظیفه → Start timer → چیپ شمارنده در هدر → Stop timer → «Time spent» وظیفه به‌روزرسانی + ردیف در بخش Time spent + فعالیت «Logged … of working time».
**معیار پذیرش:** یک تایمر فعال برای هر کاربر، جمع دقیق ثانیه‌ها، ثبت در تاریخچه.
**تست خودکار:** `CommentsTimeTest::test_timer_start_stop_accumulates`.

### ★ خلاقانه ۳ — ورود گروهی از CSV
**مسئله:** مهاجرت وظایف از ابزار دیگر (تیکتینگ/اکسل) به TaskFlow بدون ثبت دستی.
**سناریو:** Settings → Data → Download CSV template → افزودن ردیف‌ها → انتخاب فایل → Import → پیام «Import finished: N created, M failed»؛ وظایف در فهرست؛ پروژه/برچسب/مسئول ساختگی به‌طور خودکار ساخته/متصل می‌شوند؛ ردیف فاقد عنوان با پیام خطا گزارش می‌شود.
**معیار پذیرش:** گزارش موفق/ناموفق سطر به سطر + ساخت خودکار روابط + قالب نمونهٔ قابل round-trip.
**تست خودکار:** `ExportImportTest`.
